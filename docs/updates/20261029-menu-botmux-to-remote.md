# 菜单：botmux 移入「远程/桥接」并合并四项为两项

日期：2026-10-29
范围：`lib/menu-data-maintain.sh`、`maintain.sh`

## 起因

用户两条反馈：

1. **归类错**：botmux 在 `5 rag` 下不对，应归 `6 远程`。
2. **太啰嗦**：4 个 botmux 菜单项（桥状态 / 桥配置（引导） / 管理菜单 / 体检）里
   有明显重复，问能否合并。

## 为什么 botmux 该在「远程」而不是「rag」

`5 rag` 是**检索类**（lark 文档/表格 + getnote 笔记）——它的共性是「读写远端知识库」。

botmux 的本质是「**从飞书这个远端入口，遥控本机 CLI**」：人在手机/飞书上，
编程会话跑在家里的机器上。这和 SSH、tailscale 是**同一类能力**（远端接入本机），
与检索无关。故归 `6`。

分类名相应从「远程」改为「**远程/桥接**」——既保留 SSH/tailscale 的原意，
也给 botmux 这类「IM 桥」一个明确位置。将来若有别的 IM 桥（如 Slack/Discord
桥），同归此处。

## 为什么四项能压成两项

原四项及其重叠：

| 原项 | 实质 | 重叠 |
|---|---|---|
| 5G 桥状态 | `init.sh --status`：一行 OK/WARN/MISSING + 版本 + bot 数 | **就是体检的头部摘要** |
| 5H 桥配置（引导） | `init.sh guide`：只在「还没建应用」时有用 | 建完后点它只会到「已在运行」 |
| 5I 管理菜单 | `init.sh menu`：菜单第 1 项本身就是一条龙引导 | **已覆盖 5H** |
| 5J 体检 | `init.sh doctor`：会话/队列/长连接/CLI 五项检查 | 含 5G 的信息 |

合并后：

| 新项 | 实现 | 覆盖 |
|---|---|---|
| **6C botmux 桥状态体检** | `do_botmux_doctor` = 先打状态行，再打体检明细 | 原 5G + 5J |
| **6D botmux 桥配置管理** | `init.sh menu`（菜单第 1 项即引导） | 原 5H + 5I |

`do_botmux_doctor` 先输出 `--status` 的首行（给人「一句话结论」），紧接着是体检
明细 —— 用户一眼看到结论，要细节往下读，不必开两个菜单项。

命名取舍：体检项保留「桥状态」前缀，因为**普通用户搜的是「状态」而不是「体检」**；
但把原来的「（无反馈）」后缀去掉（太窄），改用更准确的「桥状态体检」。

保留 `do_botmux_status`（标注已合并）：它的三态退出码包装仍是独立有用的工具，
也避免删掉后别处引用断裂。

## 影响

- `5 rag` 从 8 项降到 6 项（只剩 lark 4 + getnote 2，分类变纯粹）
- `6 远程/桥接` 从 2 项增到 4 项
- 文档引用同步：`option-botmux/README.md`（3 处）、`option-botmux/init.sh`（1 处
  提示文案）、`docs/SH-MENU-CONVENTIONS.md`（分类清单）
- 测试：`test-botmux-option.sh` 改为断言 6C/6D 存在 + **5 段不得再出现 botmux**
  + 合并后项数上限；`test-maintain.sh` 79 项通过（原 81，少的 2 项是合并掉的
  action 断言）

## 顺带修掉的旧引用

`maintain.sh` 里 `do_botmux_status` 的注释仍写「5G」，实际已并入体检 →
改注释并说明现状，避免下一个人以为 5G 还在。
