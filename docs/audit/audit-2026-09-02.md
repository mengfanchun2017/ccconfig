## 修复记录

### 核心：bootstrap 流程解耦（#1）
`init-base.sh` `init_all_steps()` 从 4 步缩回 3 步：
- 旧：1/4 Ubuntu → 2/4 LLM → 3/4 收尾 → 4/4 init-option（内联）
- 新：1/3 Ubuntu → 2/3 LLM → 3/3 收尾（链接/服务）

可选组件恢复为独立可选步。全链：
```
init-bootstrap.sh → init-base.sh all → init-option.sh（可选）→ maintain.sh（1A 全量检查）
```
各脚本尾部引导 + dry-run 预览 + header 注释全部对齐此顺序。`init-base.sh new`（bootstrap+all 合一）保留作快捷入口，尾部仍引导 init-option + maintain。

### bootstrap-gh-auth.sh 重写（#2）
243 行 gh-auth 脚本（与 init-bootstrap.sh 重复）→ 自包含 curl\|bash 入口：
- 装 git（apt，缺失才装）
- clone ccconfig 到 ~/git/ccconfig（缺失才 clone，已有 pull）
- 提示 `bash init-bootstrap.sh`

不再 source lib/（curl\|bash 运行时 ccconfig 还没 clone，source 不到）。gh auth 交由 init-bootstrap.sh 接管。CLAUDE.md/README 一行命令描述现与实现一致。支持 `CCCONFIG_REPO` fork。

### CI 路径（#3）
`bin/test-bootstrap.sh` 从 `bootstrap-gh-auth.sh + init-ccprivate-repo.sh` 改为 `init-bootstrap.sh --non-interactive`，init-option 独立成第 3 步。

### 文件卫生（#4）

## 残余风险
- **bootstrap-gh-auth.sh git clone 代理**：新脚本 `git clone https://github.com/...` 不配代理，依赖用户 `~/.gitconfig` http.proxy 或环境变量。国内裸机若 git 代理栈未配，clone 会失败。与旧脚本行为一致（旧脚本也没配），非回归。用户需自行保证 git 代理栈可用（见 BOOTSTRAP.md "为什么是两步"）。
- **init-ccprivate-repo.sh 保留为独立入口**：未删，header 注明"已合并到 init-bootstrap.sh，本脚本作为独立入口保留"。仍被 lib/path-helper.sh、lib/status.sh 等消息引用。删除会破坏向后兼容，保留为 ccprivate-only 入口。
