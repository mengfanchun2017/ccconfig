# SH 菜单统一规范（2026-08-24，2026-09-20 扁平化改版）

> ccconfig 所有菜单的统一样式和行为约定。

## 一级菜单（data-driven，扁平结构）

使用 `menu_loop`（`lib/interact.sh`）驱动，数据在 `lib/menu-data-*.sh`：

```bash
# menu-data-maintain.sh
CAT_NAME[1]="状态"  # 灰色 --1 状态-- 标题
MENU_ENTRIES=(
    "1|A|状态检查（全量）|./maintain.sh status|bash \"\$LIB_DIR/status.sh\""
    "1|B|快速状态|./maintain.sh status --quick|bash \"\$LIB_DIR/status.sh\" --quick"
    "0| |退出||exit 0"
)
```

**schema: `cat|letter|title|cmd|action`（5 字段）**

| 字段 | 含义 |
|------|------|
| `cat` | 全局分类 ID，1-N 连续不跳号；`0` 保留给退出项 |
| `letter` | 分类内字母 A-Z；`<cat><letter>` 即执行键 |
| `title` | 显示标题，建议 ≤ 24 显示列（CJK 记 2 列） |
| `cmd` | 右侧灰色列：**绕过菜单的直接调用命令**，必须真实可跑（cwd = 仓库根） |
| `action` | 实际执行的命令或函数名（eval 上下文，可用 `$LIB_DIR` / `$CCCONFIG_DIR`） |

注：`action` 里写 `\$LIB_DIR` 转义，让展开发生在 eval 时而不是 source 时。

## 扁平化原则（2026-09-20）

**没有二级菜单，因此没有"返回上层"。**

- 一级 = 功能域（`menu-data-maintain.sh` 的 `CAT_NAME`，当前 6 个：
  状态/同步、更新、LLM、MCP、rag、远程/桥接）
- 二级 = 该域下的字母项，**选中即执行**
- 需要用户输一个参数的叶子动作（删预设、切账号），用 `maintain.sh` 里的
  `ask_run` / `ask_run_p` helper 就地 prompt，**不要为此再开一层菜单**
- 真正的列表选择器（如飞书账号挑一个 app）可以是叶子动作，按 `0` 即回主菜单，
  但它不是"上层"关系

## 渲染格式

```
  --3 LLM--
  3A  切换预设（交互）        ./maintain.sh llm
  3B  列出预设                ./maintain.sh llm list
```

- 键 `3A` 绿色加粗，无空格
- 分类标题 `--3 LLM--` 灰色加粗（分类号 + 名称）
- 标题列宽 24 显示列，右侧灰色 (`DIM`) 是 `cmd`
- 退出行 `  0   退出` 绿色加粗
- 提示 `选择:` 绿色加粗
- 分类编号连续无跳号

### 对齐必须按显示列算

`printf %-24s` 在 bash 里按**字节**补齐，中文标题会参差。统一用
`_pad_to()`（`lib/interact.sh`）计算显示宽度（非 ASCII 记 2 列）后补空格。
`tests/test-maintain.sh` 有对齐回归（所有 `cmd` 起始列必须一致）。

## 输入键

| 输入 | 行为 |
|------|------|
| `<cat><letter>` | 执行该项（`1B`、`3H`） |
| `<cat>` | 执行该分类首项 |
| `s` | 状态检查（= 1A） |
| `t` | 日志跟踪（= 1B） |
| `r` | 刷新重绘 |
| `q` / `0` | 退出 |
| `?` / `h` | 帮助 |

**不提供**裸字母跨分类匹配。九个分类每个都有 A-Z，裸字母只能命中"第一个"，
按错就执行了不想要的操作 —— 已移除。

## set -e 陷阱（必须遵守）

`_exec_entry` 失败时返回 3。在 `set -euo pipefail` 下，**裸调一个返回非零的
函数会直接杀掉整个进程** —— 表现为"点了某项（或从任何返回 3 的分支出来）
maintain.sh 自己退出了"。

```bash
# ❌ 错：f 返回 3 时 set -e 立即 exit，后面的 return 永远到不了
_exec_entry "$cat" "$letter"
return $?

# ✅ 对：捕获返回码，自己 return
_exec_entry "$cat" "$letter" || rc=$?
return "$rc"
```

调用方同理：`menu_parse "$choice" || rc=$?`。回归测试见
`tests/test-maintain.sh` §9。

## 子菜单 / 列表选择器（menu_select）

只剩"从列表里挑一个"的场景，不再用于功能分组：

```bash
local c; c=$(menu_select "标题" "选项1" "选项2" "返回")
[[ -z "$c" || "$c" = "0" ]] && return  # 0=取消
case "$c" in
    1) do_something ;;
esac
```

渲染格式：
```
  --飞书账号--
  1   <account-a>
  2   <account-b>
  3   返回

  选择 [1-3] (0=取消):
```
- 数字绿色加粗（`BOLD_GREEN`），格式 `N ` **左对齐、无括号**
- 跨 1 位/2 位序号必须同列起名（`1` 与 `10` 同列）：宽度按最大序号位数取，
  用 `%-Nd`，**不用 `%Nd`** —— 后者右对齐会让 `1` 比 `10` 多缩进一格
- 全角 `）`、半角 `)` 一律不出现在编号里；`a`/`0` 等字母键同样无括号（`a  全部`）
- 标题灰色 `--分组--` 格式
- prompt 统一 `(0=取消)`
- `0`/末项/越界/EOF 一律返回 `"0"`（取消哨值）

## 带状态的列表菜单（列表即菜单）

列表项的**状态**和**可选择性**是同一份渲染，不要再"上方打一遍状态、下方重打一遍编号选项"：

```bash
# init-option.sh: 一次渲染，编号只给组件
render_components all_names          # 编号 + 名称 + 状态 + 描述
```

约定：
- 状态图标与 `status.sh _print_option` 同形：`✅ ok` / `⚠  warn` / `✗  miss`（灰）
- 名称列 `%-12s` 对齐；`[auto]` 标记跟在名称后
- 名数组由 `collect_names` 收集，**菜单序号 = 数组下标 + 1**（渲染与解析共用一个顺序）
- 列表与提示同走 stderr（`{ ... } >&2`），避免 stdout 被重定向时错位
- 多选直接读空格分隔序号（`1 3 5`），不走 `menu_select`（后者是单选契约，空格串返 `0`）

### 附加操作走按键，不占编号

「全部安装」「退出/取消」这类**非组件**操作**不占用编号**，用按键表达 ——
占用编号会让末位组件的序号随组件数漂移（用户看到的 `12 filepull` 会变成 `12 全部安装`）：

```
  选择 [1-12] (0 取消，a 全部安装，空格多选 如 1 3 5):
```

| 输入 | 行为 |
|------|------|
| `N` / `N M` | 安装第 N（个）/ 多个组件 |
| `a` / `A` | 全部安装 |
| `0` / `q` | 退出 |
| 其他 | 无效选择，重绘 |

prompt 用**全角括号**（`（…）`）分隔键位说明，不用 ASCII `,(` 堆叠。

## 颜色变量

配色定义全部在 `lib/colors.sh`，**不要在脚本里手写 ANSI 码**（例外见下）。

### 档位选择：256 色优先，16 色兜底

| 档位 | 触发条件 | 色码形式 |
|------|---------|---------|
| 256 | `tput colors >= 256`（或 `CCCONFIG_COLOR_DEPTH=256`） | `\033[38;5;N m` |
| 16 | 否则（或 `CCCONFIG_COLOR_DEPTH=16`） | `\033[0;3Xm` |

**为什么不用 16 色当主档**：16 色的实际颜色由**终端主题调色板**决定，换主题、
切亮/暗模式、进 tmux 之后同一个色号可能被渲染成白色或近乎白 —— 这是「有时候
有颜色、有时候成功失败警告全是白的」的主因。256 色索引是固定色板，不受主题改写。

### 语义色板

| 变量 | 语义 | 256 色 | 16 色兜底 |
|------|------|--------|----------|
| `RED` | 失败/冲突/PAT 失效 | `167` 柔红 | `0;31` |
| `YELLOW` | 警告/重试/降级 | `179` 琥珀 | `0;33` |
| `GREEN` | 真的产生了效果 | `71` 柔绿 | `0;32` |
| `CYAN` | 有动静但未出结果 | `73` 柔青 | `0;36` |
| `LIGHT_BLUE` | 状态值/区块标题 | `110` 柔蓝 | `36` |
| `GRAY` | 次要信息 | `245` 中灰 | `0;90` |
| `TS_DIM` | 日志时间戳（只做锚点） | `242` 暗灰 | `0;90` |
| `NOISE` | 纯噪声行（already up to date） | `239` 极暗 | `0;90` |
| `BOLD_GREEN` | cat+letter、子菜单数字 | `1;38;5;71` | `1;32` |
| `BOLD_GRAY` | 分类标题 `--xxx--` | `1;38;5;250` | `1;90` |
| `DIM` | 直接调用命令列 / 描述文字 | `2` | `2` |

亮度统一取中等档：避开 `1;33`（亮黄）、`96`（亮青）、`196`（纯红）这类刺眼色。
`TS_DIM`/`NOISE` 两个暗灰是刻意的 —— 日志里时间戳和"没事发生"的行都该退到背景。

### 颜色开关（环境变量）

| 变量 | 效果 |
|------|------|
| `NO_COLOR` | 设了非空值就一律不上色（[no-color.org](https://no-color.org) 标准） |
| `CCCONFIG_COLOR_DEPTH` | 强制档位：`256` / `16` |
| `CCCONFIG_FORCE_COLOR` | 非 tty 也保留颜色（旧入口，兼容保留） |
| `CLICOLOR_FORCE` / `FORCE_COLOR` | 同上，事实标准入口 |
| `CCCONFIG_NO_HYPERLINK` | 关 OSC 8 超链接 |

非 tty（管道、命令替换捕获、写文件）默认清空所有色变量，输出纯文本。

### 例外：允许手写 ANSI 的场合

1. **python heredoc 内**（`init-llm.sh` 等）：python 进程里 source 不到 colors.sh，
   色码是字面量。手写时用 256 色档，与 shell 侧视觉一致。
2. **测试脚本自己的 pass/fail 输出**：独立于 lib，不必依赖 colors.sh。

### 历史坑

- `YELLOW` 原为 `1;33`（最刺眼的亮黄），已降为 `0;33` / 256 档的 `179`。
- `warn()` 落盘带 `WARN:` 前缀，但 `monitor.sh` 旧的日志着色把 `!!` 规则排在
  `WARN` 之前 → 警告被刷成红色，warning 显示成 error。规则顺序必须
  「噪声 → ERROR → WARN → SUCCESS」，作者显式标注的级别优先于正文关键词。

## 行为约定

- 顶层菜单 `0` / `q` 退出整个程序
- 不写 `read -p`（不支持 ANSI），用 `printf` + `read -r`
- `menu_select` 输出走 stderr，返回值走 stdout
- `menu_select` 从 `/dev/tty` 读输入（避开管道阻塞）
- 不需要确认步骤的操作用 `info` 输出结果，不弹 confirm
- `cmd` 列必须与 `action` 指向同一个脚本 —— 测试会校验路径与 `maintain.sh` 子命令存在
